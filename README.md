# Local Monitor — 세션 현황판

상시 웹 서버와 Codex·Claude·Antigravity 작업 감지는 Rust로 실행한다. 기존 Python 구현은 복구용으로 유지하며, 계정 사용량 조회·인증·일일 집계는 짧게 실행되는 Python 수집 어댑터를 재사용한다. macOS에서 검증했다.

현재 운영: **Rust · 5초 감지 · http://127.0.0.1:3010**. 빌드·검증·복구 절차는 [Rust 서버 운영 안내](rust-server/README.md)를 참고한다.

```bash
bash scripts/build-rust-server.sh --test
.runtime/rust-server-target/release/local-monitor-rust --port 3010 --runtime .runtime --hooks-runtime .runtime
```

아래 Python 명령은 호환·복구용이다. 같은 runtime에는 감지기 하나만 실행할 수 있다.

## 실행

프로젝트 디렉터리에서:

```bash
python3 -m local_monitor serve --port 3010 # 웹 http://127.0.0.1:3010
python3 -m local_monitor status                 # 최근 20개 세션 상태
python3 -m local_monitor snapshot               # 상세 JSON
python3 -m local_monitor watch                  # 5초마다 갱신, 새 완료 이벤트 stdout 출력
python3 -m local_monitor watch --notify         # macOS 알림도 요청
python3 -m local_monitor watch --seconds 30     # 30초 검증 후 종료
```

Ctrl-C로 종료한다. 감지기는 명령을 실행하는 동안만 동작한다. 감지기 자동 시작 서비스는 설치하지 않는다. 전용 공유 터널은 별도의 launchd 서비스로 실행한다. 같은 runtime에서 serve/watch/status를 동시에 실행할 수 없다. 웹 실행 중에는 화면이나 `/api/state`로 확인한다. `--notify` 배너 표시는 macOS 알림 허용/집중 모드에 영향을 받으며 배너 표시 자체는 검증하지 않았다.

- `.runtime/snapshot.json`: 최신 세션 목록. 후속 웹페이지에서 읽을 데이터.
- `.runtime/events.jsonl`: 감지기가 실행되는 동안 발생한 새 완료 이벤트.
- `.runtime/hooks/`: 대화 본문을 제외한 Claude 이벤트. 감지기가 꺼져 있어도 hook 수신 가능.
- `.runtime/claude-settings-*.json`: hook 설정 변경 전 백업.

`.runtime`은 개인 상태이며 Git에서 제외한다. 경로를 바꾸려면 모든 명령에 동일한 `--runtime /absolute/path`를 사용한다. 이 최소 버전에는 hook 기록 자동 정리 기능이 없다.

## Claude Code 연결

이 장비에는 감지용 hook을 추가하고 실제 터미널 응답 완료까지 검증했다. 다른 장비에서 설치하거나 제거하려면:

```bash
python3 -m local_monitor install-hooks
python3 -m local_monitor remove-hooks
```

기존 `~/.claude/settings.json` 설정과 다른 hook은 보존한다. 설치 전 백업을 남기며 동일 설치는 중복 추가하지 않는다. 제거 명령은 현재 프로젝트·Python·runtime으로 구성한 hook만 제거한다. 경로를 옮기기 전 기존 위치에서 제거한다. 감지가 안 되는 기존 세션은 새로 열어 설정을 적용한다.

수신 이벤트: SessionStart, UserPromptSubmit, Stop, StopFailure, SessionEnd, Notification, PermissionRequest, PreToolUse, PostToolUse. hook은 항상 정상 종료하고 Claude의 승인·실행 결정을 변경하지 않는다. 프롬프트, 답변 본문, 도구 입력 및 인증정보는 저장하지 않는다.

## 상태 해석

| 상태 | 의미 |
| --- | --- |
| running | 시작/활동 이벤트 관측. Codex에서는 도구 실행과 승인 대기를 세분화하지 못함 |
| completed | 해당 응답의 완료 이벤트 관측. 전체 목표 성공 보증은 아님 |
| idle | 세션이 열려 있으나 응답 완료 근거는 없음 |
| waiting_input | Claude 입력·승인 대기 이벤트 관측 |
| background | Claude 응답이 끝났지만 실행 중인 백그라운드 작업이 보고됨 |
| failed / interrupted | 오류 / 중단 |
| disconnected | 세션 종료 또는 프로세스 시작 시각 불일치 |
| unknown | 기록 누락/지원하지 않는 상태 또는 활동 근거가 10분 이상 오래됨 |

첫 스캔과 감지기 재시작 때 과거 완료 기록은 상태에만 반영하고 알리지 않는다. 새 완료는 공급자·세션·턴 기준으로 중복 억제한다. 연결이 끊겨도 완료로 바꾸지 않는다. 감지기가 꺼져 있던 동안의 알림은 재시작 시 재전송하지 않는다.

## 범위와 한계

- Codex: `~/.codex/state_*.sqlite`를 read-only로 읽고 최근 비보관 세션 최대 100개의 JSONL을 증분 추적한다. `--limit`으로 조정할 수 있다. 초기 파일 읽기는 끝 2MiB로 제한한다. 그보다 앞의 시작 이벤트는 놓쳐 unknown이 될 수 있다.
- 원본 JSONL 없이 `.jsonl.zst` 압축 기록만 남은 Codex 세션은 목록과 감지 오류에서 제외한다. 압축 기록은 읽지 않으며 완료로 판정하지 않는다. 원본이 다시 생기면 감지를 재개한다. 원본과 압축 기록이 모두 없으면 확인 실패 경고는 유지한다.
- 현재 Codex Desktop의 source는 `vscode`다. 같은 값을 쓰는 IDE 세션도 포함될 수 있다. 대화형 CLI(`cli`)와 비대화형 `codex exec`(`exec`)도 포함하며, 서브에이전트는 제외한다. CLI도 기존 최근 세션 수집 한도 안에서 추적한다. 내부 저장 형식이 바뀌면 대응이 필요하다.
- Codex는 프로세스 사망/승인 대기/도구 실행을 모두 정확히 구별하지 못한다. 10분간 활동 근거가 없으면 확인 불가로 낮춘다. 긴 정상 작업도 확인 불가가 될 수 있다.
- Claude: session registry의 PID와 **UTC 시작 시각**, 실행 경로를 대조한다. Desktop 출처의 세션도 포함한다. registry가 아직 없으면 hook-unclassified로 표시한다.
- Claude hook이 아직 수신되지 않은 세션은 검증된 실행 프로세스와 registry 상태를 보조 근거로 사용한다. `busy`는 작업 중, `idle`은 대기이며 활동 시각은 registry의 `updatedAt`을 사용한다. 최근 근거가 없는 작업 중 상태는 확인 불가로 전환하고, 이 보조 감지만으로 완료 알림을 만들지는 않는다.
- Claude Stop hook은 다른 Stop hook이 추가 작업을 유도하는 상황보다 먼저 발생할 수 있다. 이후 진행 이벤트가 상태를 갱신하지만 이미 발생한 알림을 취소하지는 않는다. hook 설치 이전에 시작되어 UserPromptSubmit을 놓친 턴은 완료 상태만 표시하고 알림은 생략한다.
- 서버는 감지 주기마다 프로세스 목록을 한 번 조회해 PID·시작 시각을 공유 검증한다. hook 디렉터리가 바뀌지 않으면 파일 목록 재탐색을 건너뛰고, 바뀌면 새 이벤트만 정렬한다. 감지 주기는 기본 5초이며 hook 기록을 삭제하지 않는다.
- 폴더/파일 존재만으로 사용 중이라고 판단하지 않는다. 세션 감지는 네트워크 호출이나 인증정보 읽기 없이 동작한다. 웹 사용량 수집은 아래의 별도 계정 조회를 사용한다.
- 웹 UI와 CLI/JSON 감지기를 제공한다. 사용량 카드는 웹 serve 모드에서 제공한다. 시스템 감지기 자동 시작 서비스는 설치하지 않는다. 전용 공유 터널은 별도의 launchd 서비스로 실행한다.

## 함께 여행하는 작업 현황

여행 배경은 설정한 위치의 날씨와 일출·일몰에 따라 바뀐다. 비·눈·안개에는 소품과 배경 효과, 저녁·밤·안개에는 랜턴, 야간 휴식에는 담요가 나타난다. 작업 상태와 탈것 단계는 날씨와 독립적이다. 날씨가 1시간 넘게 오래되거나 조회가 실패하면 여행 장면은 시간대만 표현한다. 위치는 저장값 또는 기본 서울이며 현재 위치는 버튼으로 요청할 때만 사용한다.

여행 현황판의 구름은 크기·높이·간격·투명도가 다른7개(모바일5개)가117~307초의 서로 다른 주기로 흐르며 캐릭터가 쉬는 동안에도 움직인다. 같은 타일을 반복하지 않고 각 구름이 화면 밖에서 순환한다. 산과 언덕은 비대칭 곡선, 별은 서로 다른 고정 위치, 길은 불균일한 점무늬로 표현한다. 움직임 줄이기 설정에서도 구름은 흩어진 위치에 남는다. 해는 일출~일몰, 달은 일몰~다음 일출 시간에 맞춰 하늘 위를 이동한다. 달의 위치는 천문 관측값이 아닌 밤의 진행을 나타내는 연출이다. 시간 자료가 없으면 현지06/18시를 기준으로 추정하며 움직임 줄이기 설정에서는 구름과 해·달 이동 전환을 멈춘다.

Claude 실행 확인값은 매 수집마다 현재 등록으로 재검증한다. 등록이 사라져도 종료로 단정하지 않는다. 10분 넘게 활동 근거가 없고 현재 프로세스 확인도 없는 기록은 `지난 미확인`으로 분리하며, 버튼을 눌러 원본 세션을 볼 수 있다. 현재 진행 작업이 있으면 개별 미확인 기록보다 진행 숫자를 우선 표시한다.

캐릭터 위 HP 바는 오늘 권장량 중 남은 비율이다(실제 서비스 한도와 다름). `*`는 일부 집계, 점선은 확인 불가이며 클릭하면 사용량 상세를 연다. 캐릭터 오른쪽 여행 가방은 진행 작업, 왼쪽 깃발 달린 상자는 최근30분 완료 작업이다. 각각 최대3개까지 낮게 쌓고 초과하면 `+`를 표시하며 0개는 받침만 남긴다. 정확한 개수는 툴팁·접근성 설명으로 제공하고 클릭하면 해당 작업 목록을 연다. 확인 필요 `!`, 미확인 `?`를 별도로 표시한다. 완료 시각 미확인 작업이 있으면 `*`, 연결이 끊기면 이전 수치와 `?`를 표시한다.

현황판은 왼쪽의 Codex·Claude Code·Antigravity 캐릭터 패널과 오른쪽 폴더별 작업 목록으로 구성한다. 760px 미만에서는 캐릭터를 위쪽 가로줄로 옮긴다. 진행 수는 `running`과 `background`인 관측 세션 수이며, 최근30분 완료는 현재 `completed` 상태이며 마지막 `completed_at`이30분 이내인 작업 수다. 도구와 세션 ID가 같으면 하나의 작업으로 세며, 같은 작업의 반복 응답은 합산하지 않는다. 다시 진행하거나 입력 대기·오류·미확인·연결 종료 등으로 바뀌면 완료 개수에서 즉시 제외한다. 다시 완료하면 그 시점부터30분을 계산한다. 완료 시각이 없거나 잘못된 경우 추정하지 않고 제외하며 일부 집계를 표시한다. 전체 목표 성공이나 내부 TODO 수를 뜻하지 않는다.

진행 1개는 개인 이동수단, 2~3개는 차량, 4개 이상은 비행 탈것으로 표현한다. Codex는 전동 외바퀴→탐사 로버→우주선, Claude Code는 킥보드→캠핑카→프로펠러 비행선, Antigravity는 호버보드→호버카→로켓을 탄다. 최초 관측은 즉시 표시하고 이후 단계 변경은 같은 단계가3초 유지될 때 반영한다. 숫자는 즉시 갱신하며 휴식·확인 대기·미확인에서는 마지막 탈것을 유지한 채 즉시 정차한다. 완료 발생 시 짧은 전진·추진 효과를 보여주며 움직임 줄이기 설정에서는 정지한다. 최근 완료는 발뒤의 빛 최대 5개와 초과 수로 표시하고 30분 만료 시 사라진다. 캐릭터는 확인 대기·수면·오류·확인 불가를 구분한다. 진행과 입력 대기가 함께 있으면 이동하며 확인 필요 버튼을 표시한다. 확인 불가나 수집 지연을 수면으로 표현하지 않는다. 연결이 끊기면 마지막 수치를 보존하고 이전 값으로 표시한다.

`작업 일지`는 전체 감지 세션을 연다. 도구 이름/진행 수/완료 수/캐릭터를 누르면 해당 조건의 목록이 열린다. 완료 목록은 현재 완료 상태인 최근30분의 고유 작업 목록이며, 세션 목록의 기존 20분 완료 유지 정책과 독립적이다. 검색·도구 필터, Escape로 닫기, 호출 버튼으로 포커스 복귀를 지원한다. 장식은 로컬 SVG/CSS이며 움직임 줄이기 및 숨겨진 탭에서는 애니메이션을 멈춘다.

`/api/state` 및 SSE에는 `completion_window` schema 1이 추가된다. 기존 200건 알림과 독립적으로 최근 1800초 완료를 최대 10,000건 메모리에 보관한다. 이 응답 이벤트 API는 서버 재시작/수집 공백 뒤30분, 잘못된 이벤트/시계 변경/상한 초과에 일부 집계 정보를 포함한다. 과거 이벤트를 소급 복원하지 않는다. 여행 현황판과 완료 작업 목록은 이 이벤트 합계 대신 현재 세션 snapshot의 상태와 완료 시각을 사용한다. 따라서 이벤트 window가 없는 서버도 세션 완료 시각이 있으면 작업 수를 표시한다. 현재 snapshot을 확인할 수 없으면 `—`로 표시한다. 새 모듈은 Rust와 Python 복구 서버에 모두 적용된다.

## 웹 현황판

현재 실행 주소: **http://127.0.0.1:3010** (이 장비에서만 접근 가능)

- 작업 현황은 진행·확인 필요 세션과 **완료 후 20분 이내** 세션을 한 목록으로 표시한다. 상태 우선순위 없이 실제 최근 활동 시각순으로 정렬하며 단순 조회 시각은 정렬에 영향을 주지 않는다. 완료 감지 시각은 서버에서 고정하므로 새로고침으로 연장되지 않고, 같은 세션이 재개되면 즉시 진행 상태로 바뀐다. 완료 후 연결 종료 시에도 유지 시간을 지킨다. 기본 목록에서 숨겨진 기록은 검색·필터의 전체 기록으로 볼 수 있으며 별도의 최근 완료 영역과 완료 확인 처리는 없다.
- Codex·Claude Code·Antigravity 필터, 대화/프로젝트/세션 ID 검색.
- 새 완료는 해당 행에3초 금빛 효과를 표시한 뒤7초간 금색 선과 NEW를 유지한다. 완료 토스트와 RPG 완료 배너는 띄우지 않는다. 기본6행 밖의 새 완료는 펼치기 버튼에 건수를 표시한다. 같은 세션이 재시작하면 강조를 해제하며, 움직임 줄이기 설정에서는10초간 고정 표시한다. 완료 기록과 사용자가 켠 브라우저 시스템 알림은 유지한다.
- 확인 여부는 이 브라우저에 저장. 새로고침 시 기존 알림 팝업을 재생하지 않음.
- 브라우저 알림은 상단 버튼으로 허용. 차단/미지원 상태도 안내한다. 페이지는 열려 있어야 한다. 브라우저가 백그라운드 탭을 제한하면 알림이 지연될 수 있다.
- 서버 연결 실패 시 마지막 수치를 보존하며 '연결 끊김' 표시. 감지기 오류/오래된 수집은 '수집 지연'으로 표시.
- HTTP 요청은 캐시만 읽으며 감지기를 중복 실행하지 않는다. 외부 호스트/Origin과 임의 파일 경로 요청을 거부한다.
- 완료 알림 목록은 서버 실행 중 최근 200건. 서버 재시작 시 초기화된다. 원본 이벤트 기록은 `.runtime/events.jsonl`에 남는다.
- 현재 앱으로 이동하는 기능은 없다. '세션 보기'는 현황판의 해당 행을 보여준다.

실제 Claude CLI 응답으로 페이지 팝업 1회와 완료 알림 목록, 확인 처리, 새로고침 중복 방지를 검증했다. 테스트 브라우저의 시스템 알림 권한은 denied였으므로 OS 배너 표시는 확인하지 못했다.

## Antigravity 작업 감지

`agy`의 lifecycle hook을 사용해 프로젝트별 작업 중·응답 완료·백그라운드·취소·실패 상태를 표시한다. 설치와 제거:

```bash
python3 -m local_monitor.antigravity_hook install
python3 -m local_monitor.antigravity_hook remove
```

전역 `~/.gemini/config/hooks.json`에 `local-monitor-task-detection` 항목만 추가하며 기존 항목은 보존한다. 설정 백업과 수신 이벤트는 Git에서 제외된 `.runtime/`에 저장한다. 동일 설치는 중복하지 않고, 같은 이름의 다른 설정은 덮어쓰지 않는다. 경로나 Python 실행 위치를 바꾸기 전 기존 위치에서 제거한다. 기존 세션은 새 세션을 열어 hook을 적용해야 할 수 있다.

- `PreInvocation`·도구 이벤트로 작업 중을 감지한다. `PostInvocation`만으로 완료 처리하지 않는다.
- `Stop`의 정상 종료 사유와 `fullyIdle`로 완료/백그라운드를 구분한다. 오류·취소·제한 도달은 정상 완료 알림을 만들지 않는다.
- 대화 ID·작업 폴더·시각·상태·가능한 경우 실행 프로세스 식별만 수집한다. 프롬프트·답변·도구 인자·오류 본문은 저장하지 않는다. 작업 제목은 프로젝트 폴더명을 사용한다.
- 종료된 프로세스는 연결 종료로 처리하되 최근 완료는 기존 20분 유지 규칙을 따른다. 초기 과거 이벤트는 알림을 재생하지 않는다.
- hook은 중립 JSON 응답을 반환하며 권한이나 실행 지속 여부를 바꾸지 않는다. 권한 승인 대기 상태는 아직 별도로 구분하지 않는다.
- 자동 `/usage` 조회는 `LOCAL_MONITOR_AGY_USAGE=1`로 hook 수집에서 제외한다. CLI `1.3.5`에서 실제 작업 중→완료와 필터를 검증했다. 앱·IDE는 공식 공통 hook 형식을 지원하지만 별도 실기 검증은 하지 않았다.

## 남은 사용량

현황판 상단에 계정별 **잔여 비율·한도 기간·초기화 시각·마지막 확인 시점**을 표시한다. 컨텍스트 토큰이나 프로젝트별 사용량이 아닌 로그인 계정의 한도다. 서비스별 수치를 합산하지 않는다.

- **Codex**: `codex app-server`의 `account/rateLimits/read`를 5분마다 호출. `--codex-home` 기준 계정이며 여러 limit ID와 한도 기간을 보존한다.
- **Claude Code**: `--claude-home`의 로그인 인증으로 Anthropic OAuth usage endpoint를 기본 5분마다 GET. HTTP 429에서는 Retry-After(초 또는 HTTP 날짜)를 지키고, 반복 제한 시 기본 대기 시간을 10분→20분→40분→60분으로 늘린다. 응답이 요구하는 시간이 더 길면 그 시간을 우선한다. 성공하면 5분으로 복귀하며 화면에 재조회 대기를 표시한다. macOS에서는 CLI 키체인을 우선하고 없을 때 자격증명 파일을 확인한다. 토큰은 서버 메모리에서만 쓰며 HTTP 결과/로그/argv에 노출하지 않는다. 이 endpoint는 공개 API 지원이 보장된 경로가 아니므로 향후 변경될 수 있다. User-Agent는 token-tv를 참고한 `claude-code/2.1.287`을 사용한다. 저장된 `expiresAt`(Unix 밀리초)이 지났으면 사용량 요청 전에 중단하고 아래 제한된 CLI 자동 갱신을 시도한다. 만료 메타데이터가 없거나 유효한 숫자가 아니면 실제 응답으로 판단한다. 유효한 인증 정보가 확인되면 사용량 조회를 재개한다. 이전 수치는 경고와 함께 간략하게 표시한다.
- **Antigravity**: 서버 시작 시와 정상 조회 완료 후 5분마다 `agy -p /usage --output-format json --print-timeout 30s`로 자동 조회한다. 대화형 CLI를 열어둘 필요가 없으며, 서버 실행 환경의 PATH에 `agy`가 있고 CLI 로그인이 되어 있어야 한다. 모델에 프롬프트를 보내지 않는 사용량 전용 명령이다. 실패하면 마지막 정상 값과 관측 시각을 보존하고 이전 값으로 표시하며, 재시도 대기는 10분→20분→40분→60분으로 늘고 성공 시 5분으로 복귀한다. 외부 제한 시간은45초, 출력 상한은1MiB이며 종료/시간 초과 시 자식 프로세스 그룹을 정리한다. 스레드 잠금과 `.runtime/agy-usage.lock`으로 자동 조회 중복 실행을 막는다. 기존 statusLine 수신도 유지하되 더 새로운 관측만 반영하므로 오래된 파일이 자동 조회 결과나 실패 상태를 덮어쓰지 않는다. 표시 시각은 자동 조회 완료 또는 실제 상태줄 수신 시각이다. 응답 원문과 인증 정보는 저장하거나 로그로 출력하지 않는다.
- 10분 이상 지난 값, 갱신 실패, 초기화 시각 경과는 **이전 값**으로 표시한다. 리셋 시각이 지났다고 임의로 100%로 바꾸지 않는다. 서버가 꺼지면 수집도 멈춘다.
- HTTP는 캐시만 읽고 사용량 수집은 세션 감지와 별도 스레드에서 수행한다. 재시작하면 세 서비스 모두 새로 조회하고 Antigravity는 기존 로컬 수신 파일도 함께 읽는다. Antigravity 자동 조회 결과는 메모리에 보관하며, 상태줄 수신 파일은 기존 hook이 저장한다.

Antigravity 연결/복구:

```bash
python3 -m local_monitor.usage_setup install
python3 -m local_monitor.usage_setup remove
```

설정 위치는 `~/.gemini/antigravity-cli/settings.json`. 원래 statusLine은 `.runtime/antigravity-statusline-backup.json`에 보관하며 제거할 때 해당 필드만 복원한다. 기존 사용자 스크립트가 있으면 자동으로 덮어쓰지 않는다. 기본 상태줄은 `stack_with_default`로 유지한다. 프로젝트/Python/runtime 경로를 바꾸기 전 기존 경로에서 remove한다. 다른 runtime 사용 시 설치 명령에도 `--runtime`을 맞춘다. `.runtime/usage-antigravity.json`에는 quota와 수신시각만 저장한다.

외부 공유(선택): Cloudflare Tunnel + Access로 운영할 수 있다. 공유 주소·접근 정책·계정 정보는 Git에서 제외된 로컬 `deploy/cloudflare/`에만 둔다. 관리 스크립트도 같은 로컬 폴더에 둔다. localshare는 새 공유의 실행 경로에 사용하지 않는다.

## 연결 진단 로그

수집 지연 판정은 HTTP와 SSE 응답의 `server_time`을 기준으로 브라우저의 `performance.now()` 경과 시간을 더해 계산한다. 기기 시계가 서버보다 빠르거나 느려도 15초 수집 지연 경고와 30초 시스템 정보 신선도에 영향을 주지 않는다. 실시간 메시지의 25초 무응답 판정도 단조 시계를 사용한다. 초기화·날짜 표시 등 다른 기능의 기준은 유지한다. 진단 기록의 `snapshot_age_s`는 보정된 지연, `raw_snapshot_age_s`는 기기 시계 기준 지연이고 `clock_source`로 서버 기준 사용 여부를 확인한다. 실제 수집 오류나 오래된 데이터는 계속 경고하며, 기기 시계 차이 때문에 경고 기준을 늘리지는 않는다.

연결 경고 조사 시에는 **설정 → 진단 로그 내려받기**로 경고가 발생한 브라우저의 JSON 기록을 저장한다. 10초마다 데이터 지연·마지막 실시간 메시지 경과·SSE 연결 상태·폴링 대체 여부·수집 오류 여부를 기록하고, 경고 발생/해제·연결 오류·HTTP 실패·화면 숨김/복귀는 즉시 남긴다. HTTP 상태·소요 시간과 HTTP Date 기준의 대략적인 기기 시각 차이도 기존 요청에서 수집한다. 경고 기준과 재연결 동작은 변경하지 않는다.

기록은 브라우저 저장소(`lm-connection-diagnostics-v1`)에 최대600건·24시간 보관하며, 서버에도 자동 전송한다. 평소30초마다 최대50건씩 묶어 보내고 경고·연결 오류는 약2초 뒤 우선 전송한다. 실패하면 브라우저 기록을 유지하고30초 후 재시도한다. 새로고침 후 재전송도 브라우저별 무작위 ID와 기록별 ID로 중복 제거한다. 대화 내용·대화 세션 ID/제목·URL·계정 이메일·인증 정보는 기록하지 않는다. 페이지를 닫으면 주기 수집은 멈추며 마지막 전송은 최선의 시도다. 저장소 차단/용량 부족 시에는 메모리 기록으로 계속하고, 내보낸 JSON의 `persistence_available`이 false가 된다. JSON의 `server_upload`에서 전송 상태·마지막 성공 시각·대기 건수를 확인할 수 있다.

서버 파일은 `.runtime/client-diagnostics.sqlite`(권한0600)이며 수신 시각 기준7일·전체1만 건 중 먼저 도달한 제한으로 보관한다. 수신/조회 때와 매시간 만료 기록을 정리한다. `GET /api/diagnostics?limit=200`으로 최근 기록과 서버 수신 시각·무작위 브라우저 ID를 확인할 수 있다(limit최대1000). 외부 주소에서는 기존 Cloudflare Access 로그인이 필요하다. POST는64KiB·50건·분당전체120회로 제한하고 서버에서도 필드 허용 목록을 적용한다. 읽기의 기존 CORS 설정과 별도로 쓰기는 동일 출처 또는 공유 출처만 허용한다. 공유 출처는 `LM_PUBLIC_ORIGIN`, 없으면 로컬 `deploy/cloudflare/config.json`의 `hostname`(`https://`)이며 둘 다 없으면 외부 출처 쓰기를 거부한다. 서버 재시작 후 기록은 유지된다. DB 파일은 Git에서 제외한다.

**진단 로그 내려받기·지우기**는 해당 브라우저의 기록에만 적용하며 서버 기록은 보관 기간 동안 유지된다. 사이트 데이터 삭제·시크릿 창 종료·저장 불가 상태의 새로고침은 아직 전송하지 못한 기록을 잃을 수 있다. 기존에 열어둔 브라우저는 한 번 새로고침해야 자동 전송이 시작된다.

## Git 버전 관리

소스 코드, 테스트, 사용 안내, 조사 지식, 관리 스크립트를 추적한다. 공유 주소·계정 정보가 담긴 `deploy/cloudflare/`는 로컬 전용으로 제외한다. 실행 데이터와 설정 백업이 있는 `.runtime/`, 개인 세션이 담길 수 있는 `.agent-logs/`와 `.playwright-cli/`, 로컬 환경 파일과 인증 파일은 제외한다. 이 문서의 `.agent-logs/` 링크는 작업 장비에서만 열리는 로컬 기록이다.

```bash
git status              # 변경 확인
git diff                # 변경 내용 확인
git add <변경한 파일>    # 커밋할 파일 선택
git commit -m "변경 내용"
git log --oneline       # 이력 확인
```

원격 저장소는 별도로 연결한다. 저장소 복제만으로 CLI 로그인이나 사용자 홈의 hook/statusLine 설정이 복원되지는 않으므로 위 연결 절차를 따른다.

## 소형 모니터 화면

1024×768 기본 화면은 남은 사용량3카드와 통합 작업 현황을 표시한다. 최근 완료 영역을 제거한 공간을 작업 목록에 할당하고6건 제한 없이 패널 내부에서 스크롤한다. 긴 제목은 줄임표로 표시하며 마우스를 올려 전체 제목을 확인한다. 검색·필터와 알림 설정은 접힌 메뉴에 있다. 오래된 사용량에는 경고 기호와 수신 경과 시간이 표시되고 추가 한도 그룹은 카드 내부 스크롤로 볼 수 있다. 모바일은 세로 배치로 전환한다.

화면 설정: 우측 상단 **설정 → 화면 테마**에서 라이트·다크·시스템 설정을 선택한다. 기본은 라이트이며 선택은 브라우저 localStorage에 저장된다. 시스템 설정은 OS의 밝기 테마 변경을 따라간다. 로컬 주소와 공유 주소는 서로 다른 사이트이므로 각각 선택한다.

**네온 오비트**는 짙은 남색·핑크/보라 그라데이션·민트 상태 표시를 사용하는 우주 관제 테마다. 기존 캐릭터가 투명 조종석에 탑승하며 작업 중/백그라운드에만 추진부가 작동한다. 입력 대기는 통신 신호, 실패는 경고등, 유휴는 정박 상태로 표시한다. 상단에 실제 날씨·기온을 표시하고 조종석 밖에는 낮밤·구름·비·눈·안개를 반영한다. 오래되거나 조회 실패한 날씨는 중립 배경으로 표시한다. 현재 카드·목록 크기와 HP/주간 잔여량·권장선은 유지하며, 움직임 줄이기와 숨긴 탭에서는 장식 움직임을 멈춘다.

**8비트 RPG** 테마도 선택할 수 있다. 보라색 상태창·금색 분할 게이지·리본 제목·작업 상태 아이콘을 적용한다. 완료는 해당 작업 행에서3초 효과와7초 NEW 표시로 알리고 이후 제목을 차분하게 표시한다. 별도의 완료 배너나 토스트로 목록을 가리지 않으며, 새로고침 시 지난 완료를 재생하지 않는다. 움직임 줄이기 설정을 존중하고 정확한 잔여 비율·오래된 값 경고를 유지한다.

**밤하늘 8비트**는 별도로 선택하는 테마다. 보라→파랑 밤하늘, 정적인 픽셀 십자별, 남색 패널과 금색 게이지를 사용한다. 별은 내장 SVG이며 외부 요청 없이 일부 반짝임·광원·유성 효과를 제공한다. 모든 테마의 완료 안내는 행 강조 방식을 사용한다.

**구름섬 8비트**는 연보라·하늘색 배경과 정적인 픽셀 구름·풀밭, 주황/하늘/연두색 게임기 패널을 사용하는 밝은 테마다. 사용량은 녹색 LCD 형태로 표시한다. 캐릭터나 추가 움직임 없이 기본 완료 알림을 유지하며 설정에서 선택·저장한다.

설정의 **전체 화면** 버튼으로 브라우저 Fullscreen API를 사용한다. 전체 화면 나가기 버튼 또는 Esc로 종료한다. 미지원 환경은 안내와 비활성 버튼을 표시하며 자동 진입/선택 저장은 하지 않는다.

밤하늘 8비트 테마의 작업 중·응답 완료 상태는 로컬 SVG 별 캐릭터로 표시한다. 작업 중에는 뛰는 별과 점, 완료에는 웃는 별과 반짝임을 사용하며 상태 이름은 툴팁과 접근성 레이블로 제공한다. OS의 움직임 줄이기 설정에서는 애니메이션을 멈춘다. 다른 테마는 기존 문자 배지를 유지한다.

밤하늘 테마에서는 새 완료 기록에 0.9초 별빛 효과를 한 번 표시하고, 최신 사용량이 바뀌면 막대를 0.7초 동안 이동한다. 첫 로드·새로고침·동일 값 재수신에는 효과를 재생하지 않는다. 이전 값 표시와 움직임 줄이기 설정에서는 즉시 표시한다.

밤하늘 배경에는 첫 표시 5초 후부터 약 18초마다 작은 유성이 1.8초간 지나간다. 카드 뒤에서만 보이는 장식이며 클릭을 가로채지 않는다. 움직임 줄이기 설정에서는 숨긴다.

일부 점별은6.5~10초 주기로 밝기가 변한다. 화면에 고정된 큰 별4개(넓은 화면은 상단3개·오른쪽1개, 좁은 화면은 좌우 가장자리)는 선명한 픽셀 모양 뒤에 블러 광원을 겹쳐6~9초 주기로 나타났다 사라진다. 시작 위상을 분산하며, 움직임 줄이기 설정에서는 점별을 정지시키고 광원을 약하게 고정한다.

상단 별도 브랜드 헤더와 계정 한도 문구를 제거하고 남은 사용량 제목 우측에 연결 상태·시계·설정을 통합했다. 확보된32px는 작업 현황 영역에 활용한다. 광원 별은 독립 SVG로 화면 좌표에 고정해 세로 화면의 배경 확대·잘림과 분리한다.

## 리얼 하늘 8비트

설정 → 화면 테마 → **리얼 하늘 8비트**를 선택한다. 기존 밤하늘 테마는 별도로 유지된다.

- 위치 미선택·권한 거부·위치 확인 실패 시 **서울 · 기본 위치**. 설정에서 서울·부산·인천·대전·대구·광주·제주·강릉을 선택하거나 `현재 위치 사용`을 누른다. 설정은 해당 브라우저에만 저장된다.
- 현재 위치는 사용자의 버튼 클릭과 브라우저 허용 후 한 번만 읽는다. 소수 둘째 자리로 반올림한 좌표만 브라우저에서 Open-Meteo로 전송한다. 연속 위치 추적은 하지 않는다. 선택 좌표와 마지막 날씨는 브라우저 localStorage에 보관하며 서버나 Git에 저장하지 않는다.
- [Open-Meteo](https://open-meteo.com/)의 기상 모델 자료를 15분마다 조회한다. 현재 기온·WMO 날씨 코드·낮밤 정보와 일출·일몰을 사용한다. 창밖의 실제 관측과 차이가 날 수 있으며 무료 비상업용 사용 조건에 따른다.
- 맑음·구름 조금·흐림·안개·비·눈·뇌우를 표현한다. 비/눈은 성긴 픽셀 입자, 뇌우는 번개 아이콘으로 표현하며 화면 전체 번쩍임은 없다. 패널·글자·사용량 색은 낮밤 모두 다크모드로 고정한다. 낮은 짙은 청록·청색 하늘과 해, 밤은 남색 하늘과 달·별을 사용한다. 흐린 낮은 회청색, 새벽·일몰은 어두운 자주·장밋빛 배경이다. 일출·일몰 전후30분은 새벽/노을 색상이다. 낮밤 판정은30초마다 갱신한다.
- 시간 자료가 없으면6~18시 기준의 추정 낮밤임을 설정에 안내한다. 조회 실패는 마지막 날씨와 갱신 실패를 표시하고15분 후 재시도한다. 자료가1시간 이상 지나면 이전 값으로 표시하고,6시간 이상 지나면 날씨 미확인으로 전환한다. 날씨가 없다고 임의로 맑음을 표시하지 않는다.
- 여행 현황판이 있으면 모든 테마에서 기존 15분 날씨 조회를 공유한다. 테마 전환만으로 추가 요청하지 않는다. 움직임 줄이기 설정에서는 구름·강수 애니메이션을 멈춘다. 상단 날씨 버튼을 누르면 위치 설정이 열린다.
- 브라우저가 직접 API를 호출하므로 CSP의 `connect-src`에 `https://api.open-meteo.com`만 추가 허용한다. Cloudflare Access 구성은 변경하지 않는다.

검증: `node --test tests/test_weather.cjs`, `python3 -m unittest discover -s tests`.

리얼 하늘 테마의 작업 중·완료 캐릭터는 맑은 낮 해/밤 달, 구름·안개는 구름, 비는 빗방울, 눈은 눈송이, 뇌우는 번개 구름으로 표시한다. 날씨 미확인은 별을 사용한다. 작업 중에는 열린 눈과 움직이는 점, 완료에는 웃는 표정과 고정 체크를 사용한다. 기존 밤하늘 별과 완료 행3초 효과+7초 표시는 유지한다.

리얼 하늘의 낮에는 맑음도 작고 옅은 장식 구름2개가 흐른다. 구름 조금은3개, 흐림·비·눈·뇌우는 넓고 짙은3개를 사용한다. 안개는 안개층을 강조하고 날씨 미확인은 구름을 표시하지 않는다. 구름은 상단 여백을46~79초 주기로 통과하며 카드 뒤에 머문다. 움직임 줄이기 설정에서는 화면 안에 고정한다.

8비트 테마(RPG·밤하늘·리얼 하늘·구름섬)의 사용량은 픽셀 배터리와10칸 게이지로 표시한다. 부분 칸도 실제 잔여율에 비례해 채운다. 배터리는50%초과 웃음,20%초과 진지함,20%이하 졸린 표정이며 이전 값·미확인은 회색 물음표다. 최신 잔여율이 실제로 바뀔 때만 한 번 눈을 깜빡이고 움직임 줄이기 설정에서는 멈춘다. 기본 테마는 기존 막대를 유지한다.

8비트 테마의 사용량 카드는 서비스별 작은 게임기 패널이다. Codex는 민트색 십자키, Claude는 복숭아색 원형 조작부, Antigravity는 보라색 신호 표시를 사용한다. 조작부는 장식이며 상태등 옆에 확인 상태를 문자로 함께 표시한다. 데스크톱 카드 높이는160px을 유지한다.

상단 왼쪽에는 KST 날짜·요일·시간을 `10월 12일 (월) 14:42` 형식으로 표시하며 남은 사용량 제목은 생략한다. 오른쪽에는 모든 테마에서 픽셀 날씨 아이콘·위치·기온과 설정 버튼을 배치한다. 정상 연결 문구는 숨기고 연속2회 조회 실패 시 연결 끊김, 기존15초 기준의 수집 지연, 인증 만료만 표시한다. 성공적으로 다시 조회하면 연결 경고를 해제한다. 모바일에서는 경고를 상태 표시줄 아래 행에 둔다.

사용량 패널은 주간 하루 권장량과 `초기화까지 3d 18h`를 표시한다. 권장량은 남은 주간 비율을 초기화까지의 소수 일수로 나눈 값이며, 24시간 미만에는 초기화 전 사용 가능량으로 표시한다. 초기화 시각 미확인·경과 시 권장량을 숨긴다. 패널 클릭 또는 Enter/Space로 서비스별 상세 팝업을 열면 한국 시간 기준의 정확한 초기화 날짜, 계산 근거, 마지막 확인 시각을 볼 수 있다. Esc·닫기·바깥 클릭으로 닫으며, 이전 값 기준 권장량은 구분해서 표시한다.

기존 잔여량 게이지는 현재 잔여색 뒤에 오늘 감소한 구간을 어두운 빗금으로 남기고, 집계 시작 지점에 작은 눈금을 표시한다. 별도 텍스트나 패널 높이는 추가하지 않는다. 시작점은 KST06:00 이후 첫 정상 관측이며, 당일 주간 한도가 초기화되면 새 한도 구간의 첫 관측으로 바뀐다. 실제 오늘 누적 사용량은 기존 방식대로 초기화 전후를 합산한다. 계정 집계가 없거나 초기화 시각이 누락·경과한 경우에는 기존 잔여량 게이지만 표시한다. 밝은/어두운 테마의 연속 막대와 8비트 테마의 픽셀 막대에 모두 적용한다.


일일 사용량은 서버에서 KST 06:00~다음 날06:00 기준으로 `.runtime/daily-usage.json`에 저장한다(권한0600, 원자적 교체). 주간 한도별로 첫 정상 관측의 잔여량을 기준으로 다음06:00 또는 초기화까지의 시간에 배분한 오늘 권장량을 고정하고, 기준 대비 최저 잔여량의 차이를 오늘 사용량으로 누적한다. 수치는 전체 주간 한도 기준 `%p`다. 실제 초기화 시 이전 구간은 리셋 전 기록으로 보존하고 새 잔여량과 오늘 남은 시간·다음 초기화까지의 시간으로 권장량을 다시 계산한다. 새 구간의 사용량은 0부터 집계한다. 초기화 시각이 같아도 1%p 이상 회복해 100%가 되거나 최초 잔여량보다 1%p 이상 증가하면 새 할당으로 처리한다. 일반적인 소폭 보정은 기존 집계를 유지한다. 초기화 시각의 5초 이내 오차는 같은 구간으로 취급한다. 이전 초기화 시각에 도달하고 다음 초기화 시각이 확인될 때 새 구간을 만들며, 초기화 전 일정 보정은 최초 권장량·사용량 기준을 유지하고 불확실성을 표시한다. 초기화 시각이 잠시 누락돼도 사용량 집계는 이어가고 권장량만 숨긴다. 첫날 및06:00 이후 지연 관측은 실제 집계 시작 시각부터만 계산하며 소급 추정하지 않는다. 같은 관측의 재수신·브라우저 새로고침·서버 재시작으로 중복 집계하지 않는다.

과거 초기화 시각 오차로 중복된 구간은 서버 수집기를 중지한 뒤 `python3 scripts/repair-daily-usage.py`로 미리 확인하고, `--apply`로 복구할 수 있다. 같은 초기화 시각(최초 구간 기준 5초 이내)의 연속 구간만 병합하며 최초 권장량과 최저 잔여량을 보존한다. 원본은 `.runtime/backups/`에 권한0600으로 백업하며 실행 중인 수집기가 있으면 중단한다. 복구 후 서버를 재시작한다.

Codex의 로컬 account_id, Claude의 로컬 계정·조직 식별자를 해시로 분리해 저장하며 원문 식별자·토큰을 API나 일일 기록에 넣지 않는다. 계정 구분을 확인할 수 없는 경우 일일 집계를 보류한다. 현재 Antigravity bridge에는 계정 식별값이 없어 `일일 집계 · 계정 확인 필요`로 표시하며 기존 잔여율과 초기화 시간만 제공한다. 저장 오류·집계 지연·권장 초과·일부 미집계는 상세 팝업에서 확인할 수 있다. 기록 파일은 각 계정/한도의 최근 사용일 상태를 유지하고32일 이상 갱신되지 않은 항목은 정리한다.

Claude 접근 토큰 만료 시 CLI 자동 갱신을 기본 활성화한다. 도구·사용자 훅·플러그인·MCP·세션 저장을 끈 짧은 Haiku 요청1회로 CLI 자체 갱신을 유도하며 소량의 모델 사용량을 소비한다. `--safe-mode`를 사용하고 키체인 인증을 끄는 `--bare`는 사용하지 않는다. 실행은 최대55초, 성공·실패 모두 최소1시간 간격이다. 실행 전에 `.runtime/claude-refresh.json`에 다음 가능 시각을 권한0600으로 원자적으로 저장하여 재시작해도 제한을 유지한다. 스레드·파일 잠금으로 중복 실행을 방지하고 출력·오류 원문은 보관하지 않는다. 상태 기록에 오류가 있으면 자동 시도를 보류한다. 기본 `~/.claude`는 CLI 기본 인증 범위를 유지하고, 다른 `--claude-home`만 `CLAUDE_CONFIG_DIR`로 전달한다. 자식 프로세스의 API키·별도 토큰·공급자 환경 변수는 제거한다.

자동 갱신 중·재시도 대기를 카드에 표시하고 상세 창에 다음 시도 가능 시각을 표시한다. 만료 중에도15초마다 로컬 인증 정보를 다시 확인하며 외부 CLI에서 갱신해도 복구된다. 갱신 시도 직후 사용량을 재조회해 실제 복구를 확인하고 성공하면5분 주기로 복귀한다. 자격 증명 없음·API401/403·429는 CLI 자동 갱신을 실행하지 않고 기존 로그인 안내·조회 대기를 유지한다. 브라우저 재로그인은 자동 실행하지 않는다. 끄려면 서버 환경에 `LM_CLAUDE_AUTO_REFRESH=0`을 지정하고 재시작한다.

밤하늘·리얼 하늘8비트 테마의 백그라운드 작업은 캐릭터가3초 주기로1~2px 부유하고 두 픽셀 점이8방향 궤도를 도는 모습으로 표시한다. 리얼 하늘은 날씨 캐릭터를 유지하며, 움직임 줄이기 설정에서는 정지한다. 기본 테마의 텍스트 배지는 유지한다.

서비스 카드 옆 시스템 카드는 서버 Mac 전체의 상태를 약10초마다 수집해 표시한다. 클릭하면 메모리 사용/전체(GiB), 메모리 압력, 스왑, 수집 시각을 볼 수 있고 설정에서 표시를 끌 수 있다. CPU는 전체 코어 누적tick 차이를0~100%로 정규화한다. 메모리는 활성+비활성+유선+압축-파일캐시-회수가능 페이지 기반 추정치로 활동 모니터와 다를 수 있다. CPU85% 이상10초 지속 또는 메모리 압력 주의/높음일 때 강조한다. 수집 실패·30초 초과 지연이면 마지막 정상 값을 유지하고 `이전 값`과 경과 시간을 표시한다.


통신은 최초 `/api/state` 요약 조회 후 `/api/stream` SSE로 변경분을 수신한다. 공용 서버 요약 캐시는1초마다 기존 수집 결과를 읽으며 외부 사용량 API를 추가 호출하지 않는다. 시스템 수치·변경/삭제 세션·사용량 요약·완료 이력을 변경 시 전송하고, 유휴 연결은10초 heartbeat로 확인한다. 사용량 계산 구간은 `/api/usage/{provider}`로 팝업을 열 때 조회한다.256개 메시지 이력과 instance:revision 커서로 재접속하며, 이력이 없거나 서버가 바뀌면 현재 상태를 기준으로 다시 동기화해 오래된 완료 알림을 재생하지 않는다. SSE 장애 시5초 폴링으로 대체하고 복구되면 폴링을 중단한다. 시계·초기화 남은 시간은 브라우저에서 갱신하며 CPU 변경만으로 작업·사용량 DOM을 교체하지 않는다. `/api/state`의 daily 필드는 요약으로 축소됐으므로 상세 계산이 필요한 소비자는 상세 API를 사용한다.

시스템 카드는 서비스 카드 옆에 CPU·RAM·SWAP 현재 값과 최근30분 그래프를 표시한다.4개 카드 높이는160px이며,600px 이상4열,600px 미만1열이다. 설정에서 시스템 카드를 숨기면600px 이상은3열로 돌아간다.600~799px에서는 상태 문구를 작은 상태등으로 표시하고(마우스를 올리면 상태 문구 확인), 보조 한도의 초기화 시간을 다음 줄에 표시한다. 주간 한도의 오늘 사용/권장·초기화 카운트다운은 기본 표시하며, 전체 상세는 패널 클릭으로 확인한다.

시스템 수집 주기는10초이다. 그래프는 성공적으로 수집한 값의10초 평균이며 최대180개를 서버 메모리에 보관한다. 새로고침 시 유지되고 서버 재시작 시 초기화된다. CPU·RAM은0~100% 고정 축, SWAP은0에서 최근 사용량에 맞춘 GiB 축으로 표시한다. 누락 구간을 연결하거나0으로 채우지 않는다. 수집 실패·지연 시 마지막 정상 값은 황색으로 유지하고 `이전 값 · n초 전`으로 구분한다. 정상 수집 기록이 없는 항목만 `—`로 표시하며, 실패한 시간에는 과거 값을 그래프에 복제하지 않는다. SSE 초기 동기화에는 전체 기록, 이후에는 새 지점과 보관 범위만 전송한다. 카드 클릭 시 스왑 사용량 / 현재 할당 크기를 확인할 수 있으며 할당 크기는 macOS가 조정하는 값으로 고정된 최대 용량이 아니다.

화면 글꼴은 모든 테마에서 [Neo둥근모 v1.600](https://neodgm.dalgona.dev/)을 사용한다. 공식 WOFF2를 `local_monitor/web/fonts/neodgm.woff2`에 포함하여 외부 폰트 요청 없이 제공한다. 원본 글꼴은 수정하지 않았으며 SIL OFL1.1 라이선스·저작권 안내는 같은 폴더의 `OFL.txt`에 보존한다.

CORS는 사용자 설정에 따라 모든 Origin을 허용한다(`Access-Control-Allow-Origin: *`). 폰트·API·SSE·오류 응답에 적용하고 OPTIONS 사전 요청을 처리한다. 지원 메서드는 GET/OPTIONS이며 자격 증명 포함 교차 출처 요청은 허용하지 않는다. Host 검사는 유지하며 Cloudflare Access 인증 정책은 별개로 유지한다.

시스템 수집 오류는 단계(CPU·메모리·메모리 압력·SWAP), 원인 분류, 예외 종류, 시각, 연속 실패 횟수만 기록한다. 오류 메시지·명령 출력·인자는 기록하지 않는다. 최초 오류·오류 종류 변경은 즉시 기록하고 같은 오류의 반복은60초마다 기록하며 정상 복구도 한 번 기록한다. 현재 서버 로그는 `/tmp/2026-10-14--local-monitor-rust-web-3010.log`이며 재시작 시 덮어쓸 수 있다. 시스템 상세에는 마지막 오류의 한국 시각·원인·연속 실패 또는 이후 복구 여부를 표시한다. 마지막 오류 정보와 마지막 정상 값은 서버 메모리에 보관하며 재시작 시 초기화한다.

서버는 변경 없는 세션 데이터를 내부에서 재사용하며 외부 API에는 독립 복사본을 제공한다. `.runtime/snapshot.json`은 내용 변경 시 즉시 저장하고, 변경이 없으면 60초마다 관측 시각을 저장한다. 화면의 실시간 감지 시각은 계속 5초마다 갱신한다.

Rust 전환 시 기존 일일 집계·진단 DB·사용량 재시도 시각을 보존했다. 사용량 조회 중에는 Python 어댑터와 제공자 CLI가 잠시 실행되므로 서버 본체의 RSS만으로 전체 순간 메모리를 판단하지 않는다.

### Antigravity 보관·삭제 제외

데스크톱 `~/.gemini/antigravity`에서 감지된 세션 ID의 대화 파일과 annotation을 함께 확인한 경우, `archived:true`인 세션은 현황판과 새 완료 알림에서 제외한다. 복원하면 원래 작업 상태·완료 시각으로 돌아오며 복원 자체는 새 완료가 아니다.
동일 저장 디렉터리에서 두 파일이 모두 사라진 것을 연속 두 번 확인하면 삭제로 제외한다. 최초부터 파일이 없거나 디렉터리가 바뀌거나 읽기에 실패한 경우에는 삭제로 판단하지 않는다. 관측 이력은 hooks runtime의 `antigravity-lifecycle.json`에 저장하여 재시작 후 재사용한다. 앱 파일은 읽기만 한다.
CLI 전용 세션과 CLI/데스크톱 양쪽에 같은 ID가 있는 경우에는 이 규칙을 적용하지 않는다. 수집 시작 전에 삭제되어 존재 이력이 없는 세션은 판별할 수 없다. 요약 DB 부재만으로 삭제를 판단하지 않으며 Claude·Codex 수집 조건은 이번 변경 대상이 아니다.

현황판 왼쪽 도구 이름은 숨기고 캐릭터 툴팁으로 제공한다. 오늘 HP와 주간 잔여량은 같은 너비의 두 줄 게이지로 캐릭터 옆에 정렬한다. 캐릭터를 누르면 해당 도구의 폴더별 작업을 필터링하고, 설정의 전체 도구 버튼으로 해제한다. 캐릭터 아래의 중복 완료 미리보기는 숨긴다. 오른쪽 목록은 전체 cwd로 묶어 같은 이름의 다른 폴더를 구분한다. 표시 중인 가장 가까운 상위 폴더 아래에 하위 폴더를 배치하고, 작업 없는 중간 경로는 `src/ui`처럼 압축한다. 하위 폴더는 부모 아래에 폴더명·작업수 칩으로 가로 배치한다. 같은 부모 아래에서는 선택한 칩 하나만 칩 줄 아래에 펼치며, 같은 칩 재클릭이나 내용 헤더의 접기로 닫는다. 칩은 기본 두 줄이고 초과는 `+N개`로 펼쳐볼 수 있다. 입력 대기·오류 등 확인이 필요한 작업은 칩에 작은 표시로 알린다. 최상위 폴더는 기본 펼침이다. 선택과 접기 상태는 갱신에도 유지하며 새로고침 시 하위 선택은 초기화한다. 폴더 제목의 수치는 하위 작업을 포함하며 부모를 접으면 후손 전체가 숨겨진다. 다시 열면 하위 칩 선택을 유지한다. 들여쓰기는 단계당10px·최대30px로 제한한다. 도구 필터나 완료 만료로 부모가 사라지면 자식은 남은 상위 폴더에 맞춰 재배치한다. 폴더 접기를 제공하며 상태 필터와 폴더·작업 검색 입력은 생략한다. 진행·백그라운드 작업은 프로젝트별 헤더 숫자로 집계하고 행에서는 숨긴다. 전체 집계는 표시하지 않는다. 진행 작업만 있는 하위 폴더의 칩·상세는 숨기되 프로젝트 집계에는 포함한다. 확인 필요·오류·상태 미확인·최근30분 완료 작업에는 메시지 최대 두 줄과 선택지 한 줄 미리보기를 표시한다. 폴더 제목 줄은 약26px, 작업 행은 최소64px(420px 이하80px), 폴더 간격은4px다. 데스크톱은 높이122px의 캐릭터·사용량 통합 카드 3개를 배치하며, 사용자 모니터에 맞춘 현재 크기를 유지한다(세부 기준은 AGENTS.md 참조). 많은 작업은 목록 내부에서 스크롤한다. 입력 대기·오류·현재 미확인과 최근 완료를 행으로 표시하며, 오래된 미확인 및 종료 기록은 작업 일지에서 확인한다. 재개·만료·수집기에서 제거된 완료 작업은 목록에서 빠진다.

진행/완료 작업량은 캐릭터 양옆의 가방/상자로 표시하며 중복 숫자 행은 생략한다. 작업 목록은 폴더 패널에 모으고, 확인이 필요한 도구 상태는 각 캐릭터 아래에 표시한다.

폴더 헤더에 폴더명과 전체 경로를 표시하며 작업 행은 도구·제목·상태로 구성한다. 경로가 없으면 폴더 미확인으로 묶는다. 좁은 화면에서는 경로를 툴팁으로 제공한다.

HP 권장초과는 권장량 대비 초과 비율(+N% 초과)을 표시한다. 권장량0인 경우에는 상대비율 대신 실제초과 %p를 표시한다.

최근 완료 목록의 시간은 캐릭터 얼굴 바로 오른쪽의10px 파이 게이지로 표시한다. 미완료 행도 파이 자리를 비워 작업명 시작 위치를 맞춘다. 30분 동안 시계방향으로 비워지고 만료 시 항목이 사라진다. 정확한 시간은 툴팁/접근성 설명으로 제공하며 연결 끊김 시 마지막관측값을 유지한다.

Antigravity는 검증된 데스크톱 annotation의 실제 대화 제목을 작업명으로 표시한다. 폴더 정보는 cwd로 유지하며, 제목을 읽을 수 없거나 CLI 전용 세션이면 기존 폴더명으로 표시한다. 제목 변경은 다음 수집 때 반영된다.

Antigravity 일일 집계는 로컬 consumer 로그인 정보의 이메일을 정규화한 해시로 계정을 구분한다. `id_token`이 갱신 후 사라져도 `id_token_email`로 같은 계정을 유지하며, 양쪽 이메일이 다르면 집계를 보류한다. 이메일이 없는 기존 ID token은 subject 식별을 유지한다. 이전 subject 기록과 이메일 기록은 임의로 병합하지 않으므로 전환 첫 관측은 부분 집계로 시작할 수 있다. 원문 이메일·토큰은 집계에 저장하지 않는다.

### 통합 현황판 (2026-11-02)
상단은 날짜·날씨·설정만 표시합니다. 왼쪽은 캐릭터별 일일 HP와 주간 잔여량·권장선·초기화 정보, 하단은 시스템 요약입니다. 오른쪽은 폴더별 작업 목록이며 최근 30분 완료/재개 제외 조건을 유지합니다. 좁은 화면에서는 두 패널을 세로로 배치합니다. 사용량과 시스템 요약을 누르면 기존 상세 창을 엽니다.

UI 변경 시 [AGENTS.md](AGENTS.md)의 모니터 크기 유지 기준을 따릅니다. 현황판 하단 안내 영역은 없으며 작업 일지는 설정에서 엽니다.

### 작업 행 얼굴 아이콘의 상태

얼굴은 도구별 원래 색과 형태를 유지하며, 오른쪽 상태 문구가 정확한 상태를 설명합니다. 아이콘/열/행/패널의 크기는 유지합니다.

| 상태 | 표정·표식 | 동작 |
| --- | --- | --- |
| 진행 중 | 집중한 눈 | 1.4초 주기로 좌우 24도 기울기 |
| 백그라운드 | 차분한 눈 | 5초 주기로 좌우 12도 기울기 |
| 입력 대기 | 기다리는 눈·주황색 점 | 정지 |
| 오류 | 찡그린 눈·붉은 마름모 | 정지 |
| 확인 필요 | 불확실한 눈·회색 점 | 정지 |
| 완료 | 편안한 눈 | 관측 중 완료로 전환할 때만 한 번 반짝임 |

초기 표시·필터 변경·다른 행 갱신에는 완료 효과를 재생하지 않습니다. 연결 끊김 시 마지막 관측 표정을 유지하고 채도를 낮추며 움직임을 멈춥니다. 숨긴 탭과 동작 줄이기 설정에서도 움직임을 끕니다. 종료·중단·삭제·보관 등의 기존 목록 포함/제외 조건은 변경하지 않습니다.

이중 게이지의 윗줄은 오늘 HP, 아랫줄은 주간 잔여량입니다. 권장선은 주간 게이지에 유지하며 오늘 사용량과 초기화 정보를 아래에 모읍니다. 보조 한도는 사용량 상세에서 확인할 수 있습니다. 초과·미확인·이전 값·로그인 안내는 계속 표시합니다.

완료된 작업 행은 도구와 관계없이 옅은 민트 배경으로 표시하며, 완료 직후 14% 혼합에서 30분 동안 기본 배경까지 옅어집니다. 파이 게이지와 같은 시계를 사용하고 연결 끊김 시 함께 멈춥니다. 작업 재개 시 배경은 즉시 제거됩니다.

### 폴더 목록 전환

폴더·작업의 추가와 삭제, 정렬 위치 변경을 약 400ms의 짧은 전환으로 연결합니다. 새 폴더는 공간이 열리는 모습으로, 새 행은 4px 이동과 함께 나타납니다. 삭제된 항목은 실제 목록에서는 즉시 빠지고 클릭·키보드·접근성 대상이 아닌 시각적 잔상만 잠깐 사라집니다. 마지막 작업이 빠진 폴더는 통째로 퇴장합니다.

스크롤 중 갱신되면 화면에 남아 있는 행의 위치를 기준으로 스크롤을 보정합니다. 기준 항목이 모두 사라지거나 목록이 짧아져 스크롤 한계에 닿으면 가능한 범위까지만 유지합니다. 포커스된 행이 삭제되면 가까운 생존 항목으로 이동합니다. 빠른 연속 갱신은 현재 보이는 위치에서 새 전환을 시작합니다.

초기 로딩·명시적 도구 필터 변경·리셋·연결 복구는 목록 전환을 생략합니다. 동작 줄이기, 숨긴 탭, 연결 끊김, 사용자 스크롤·화면 크기 변경 시 진행 중 효과를 취소합니다. 수동 폴더 접기는 기존 즉시 동작을 유지합니다. 패널 치수와 목록 내부 스크롤 구조는 바뀌지 않습니다.

### 캐릭터 배경 이동

각 도구의 캐릭터 뒤에서 길의 풀·돌, 언덕, 먼 산이 왼쪽으로 흐릅니다. 진행 1개는 길 8px/s, 2~3개는 14px/s, 4개 이상은 22px/s로 제한하며, 백그라운드 작업만 있으면 4px/s로 느리게 이동합니다. 언덕은 길 속도의 22%, 먼 산은 6%로 이동해 거리를 표현합니다. 일반 출발·정지는 600ms 동안 가감속하고, 상태 미확인·연결 끊김·숨긴 탭·동작 줄이기 설정에서는 즉시 멈춥니다. 재개할 때 숨긴 시간만큼 위치를 건너뛰지 않습니다. 구름·날씨 효과와 카드·게이지 크기는 유지합니다.


### 대화 메시지 미리보기

세션 snapshot의 optional `preview`에는 최신 assistant 본문(최대8,000자), 구조화 질문(최대3개)과 질문별 선택지(최대6개)가 포함된다. 라벨200자·설명500자·질문1,000자로 제한한다. Codex JSONL의 assistant 응답/최종 메시지/질문 호출, Claude의 해당 세션 프로젝트 JSONL만 읽는다. 새로운 턴에서 이전 미리보기를 지우며, Claude는 새 prompt hook 시각 이전 메시지를 다시 표시하지 않는다. 동기 Codex 질문 호출은 입력 대기, 해당 결과 수신은 진행으로 전환한다.

원본에 `선택지`라는 제목으로 구분한 목록은 화면에서 미리보기로 분리한다. 다른 번호 목록을 임의로 선택지로 해석하거나 AI 요약을 만들지 않는다. 선택지는 읽기용이며 클릭 시 작업 일지에서 수집한 본문과 선택지를 확인한다. Antigravity의 현재 hook에는 본문이 없어 대체 안내를 표시한다. 원문이 없거나 읽을 수 없는 세션도 같은 안내를 사용한다.

본문은 기존 접근 제어가 적용된 `/api/state`·SSE와 private `.runtime/snapshot.json`에 포함된다. 사용자 프롬프트·시스템 지시·추론·일반 도구 결과를 미리보기로 수집하지 않는다. 기존 hook 파일과 진단 로그의 본문 미보존 정책은 유지한다. HTML은 실행하지 않고 텍스트로 표시한다.


Claude 미리보기 복구: 새 prompt와 완료 Stop에서는 기존 읽기 위치를 초기화하고 최근2MiB 범위의 원문을 다시 확인한다. 새 prompt 이전 시각의 답변은 계속 제외한다. 일시 읽기 실패 시 본문과 읽기 위치를 함께 무효화해 같은 파일이 복구돼도 다시 읽는다. 최근30분 완료인데 본문이 없으면30초 간격으로 재확인한다. 정상 본문이 있으면 증분 수집을 유지하며 복구 때문에 완료 알림/시각을 다시 만들지 않는다. 세션의 optional `preview_error`는 `missing`, `read_failed`, `no_message`로 원인을 구분하고 원문·오류 본문은 진단에 기록하지 않는다.

### 두 줄 메시지 요약 (선택)

`tools/preview-summary`는 **Codex SDK 0.167.0 / gpt-6-luna**로 최근 완료와 확인 필요
메시지를 두 줄로 요약한다. 원문은 작업 일지 상세에 그대로 남는다. 요약 대기 중에는
`확인 중`만 표시하고, 호출·응답 검증 실패 시 기존 원문 미리보기를 표시한다. 실패 후
재시도 중에는 원문을 유지하며 성공하면 두 줄 요약으로 바뀐다. Node.js 18 이상과 `codex` CLI의
ChatGPT 로그인이 필요하며 호출은 해당 Codex 계정 사용량을 소비한다.

```sh
npm ci --prefix tools/preview-summary
node tools/preview-summary/worker.mjs .runtime
```

모니터 서버와 별도 프로세스로 유지한다. 실행 인자는 모니터의 runtime 디렉터리이며
`--once`를 추가하면 대상 한 건만 처리하고 종료한다. `LOCAL_MONITOR_CODEX_BIN`으로
CLI 실행 파일을 지정할 수 있다. 기본 로그인 위치는 `CODEX_HOME` 또는 `~/.codex`이며
파일 기반 `auth.json` 인증을 공유한다. 키체인 전용 인증은 별도 연결이 필요하다.

worker는 별도 비공개 Codex 홈과 빈 작업 디렉터리에서 ephemeral 실행한다. 모니터에
새 대화가 쌓이지 않는다. 프롬프트에는 이미 수집된 assistant 본문·질문만 넣는다.
프로젝트 지침, shell, 웹 검색을 사용하지 않는다. 요약 캐시
`.runtime/preview-summaries.json`은 원문·상태와 일치할 때만 표시하며 24시간/128건으로
제한된다. 요청은 한 번에 하나, 60초 제한, 시간당 최대60회이며 실패한 입력은 최대3회
재시도한다. 원문이 같으면 화면 갱신·worker 재시작에도 재호출하지 않는다.

중지하려면 worker에 SIGTERM을 보낸다. 캐시 파일을 삭제하면 다음 수집부터 요약 대기
표시로 돌아간다. worker 중지·호출 제한은 실패로 간주하지 않아 대기 표시가 유지된다.
서버 수집과 상태 판정은 worker 실행 여부와 독립적이다.

요약 형식: 첫 줄은 `목적 · …`, 둘째 줄은 아래 행동 중 하나와 구체적인 내용이다.

| 행동 | 의미 |
| --- | --- |
| ▶️ 이어가기 | 다음 실행 작업이 명확함 |
| 🔀 결정하기 | 대안 비교나 중요한 선택이 선행되어야 함 |
| 🔎 확인하기 | 검토·검증이 남음 |
| ⏳ 기다리기 | 외부 응답·CI·배포 진행 대기 |
| 🧹 정리하기 | 서버 종료·작업 공간 정리가 남음 |
| ✅ 마무리 | 필요한 작업과 확인이 끝남 |
| ⛔ 막힘 | 오류·권한·필수 정보 부족으로 진행 불가 |

근거가 부족할 때만 `❔ 확인 필요`를 사용한다. 모델이 반환한 action을 고정 이모지와
행동명으로 변환한다. 여러 조건 중 다음 행동을 좌우하는 선행조건을 표시하며,
원문에 없는 추천을 만들거나 미완료·미검증 상태를 완료로 바꾸지 않도록 지시한다.
